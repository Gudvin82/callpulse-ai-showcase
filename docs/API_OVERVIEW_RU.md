# Обзор mock API

## Назначение

Mock API - безопасная локальная демонстрация публичных API-контрактов CallPulse AI. Он возвращает только синтетические данные, не подключается к телефонии, CRM или AI-провайдерам и не совершает реальных звонков.

Базовый адрес: `http://localhost:8090`

## Наблюдение и обзор платформы

- `GET /health` - доступность mock API.
- `GET /api/platform/overview` - включённые продуктовые контуры и режим `mock`.
- `GET /api/ops/health` - демонстрационный срез операционных статусов.

## Звонки и CRM

- `GET /api/calls` - список синтетических карточек звонков.
- `GET /api/calls/:id` - карточка одного звонка.
- `GET /api/crm/leads` - демонстрационные лиды.
- `POST /api/crm/leads` - создание синтетического лида для локальной демонстрации.

## Control Plane

- `GET /api/control/campaigns` - кампании обзвона и их конфигурация.
- `POST /api/control/campaigns` - создание демонстрационной кампании. Заголовок `Idempotency-Key` защищает от повторного создания в рамках сессии mock API.
- `GET /api/knowledge/bases` - версии и статусы баз знаний.
- `GET /api/consents/dnc` - пример статуса согласий и DNC без публикации персональных данных.
- `GET /api/billing/usage` - демонстрационные агрегаты использования и бюджета.

## Контракты и ограничения

- Все ответы являются демонстрационными и хранятся только в памяти процесса.
- Синтетические телефоны и имена не являются клиентскими данными.
- Mock API не подтверждает фактическую производительность, доступность или интеграцию с реальными провайдерами.
- В production командные операции должны проходить через аутентифицированный Control API, журнал аудита и серверную tenant-изоляцию.
